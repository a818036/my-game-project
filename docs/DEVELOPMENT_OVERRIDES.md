# 開發覆寫紀錄

此文件記錄玩家對遊戲規格的明確覆寫，不改寫 `docs/source` 中的原始手冊。新覆寫依日期排序，較新的明確要求優先。

## SRC-2026-10-29-01：規則來源更新至 v3.17

- **來源**：玩家提供 `神洲三國_規則手冊_v3.17.md`，原檔未修改地加入 `docs/source/`；SHA-256、位元組與行數記錄於 `SOURCE_MANIFEST.json`。天生技來源仍為 v1.10。
- **效力**：v3.17 為目前規則基準。主角投入殺傷性戰場時須以已結算場景資料呈現物理連鎖、視距與戰後影響；不得虛增傷亡或讓非殺傷行動致死。該機制屬敘事呈現，不創造新技能或改變結算。
- **存檔**：v3.15／v3.16 v6 存檔事件前綴及既有結果不變；遷移只追加版本事件，必要時另追加落後的歷史內容更新。
- **目前切片**：戰役可選附結構化場景清冊，記錄示例物件、未觸發的條件性因果鏈與雙方觀察位置。清冊經 ID 參照驗證並能傳入旁白上下文；每條鏈明示「尚未觸發或結算」，不新增物理結果、傷亡或技能效果，也不改動舊存檔。
- **尚未完成**：§9.3C 是敘事規則，並未要求完整物理模擬。現有戰場資料僅有有限視距幾何、預置因果鏈／傷亡及具名名冊，無法涵蓋所有戰役的有形危險、逐環因果、目擊視野與後效；真實模型是否能依七項要求呈現也仍待人工驗收。資料不足時敘事仍須保守省略，不得虛構補足。

## OV-2026-10-21-01：行動計畫介面與處理

- **來源**：玩家 2026-10-21 明確要求，目標為目前 PR #3。
- **覆寫範圍**：介面與回合互動，覆寫 `docs/GAME_REQUIREMENTS.md` R12 及 `docs/ACCEPTANCE.md` A27 中四個互斥單選選項的表述；不修改規則 v3.15 或天生技 v1.10 原文。
- **新行為**：四項行動改為可複選 checkbox，點選不執行；textarea「補充說明」接受行動順序、對象、方法、條件或註記；明確「送出行動」一次提交一份計畫。
- **時間／資源**：一份成功計畫至多推進一個回合、自動引擎只執行一次。新增的行動負荷點數與能力未指定的數值是標示為可調整的工程參數，非原作者規則。資產仍按各已選行動的既有規則逐筆結算；不得因複選重複扣回合或重跑後台。
- **衝突**：出現超出工程負荷、互斥地點或順序衝突時先列明項目與原因，不執行；玩家可調整選取後再次提交。不得靜默丟棄項目。
- **自由文字**：此階段不接 AI。補充說明目前不轉成引擎條件；有選項時，送出前需讓玩家確認只執行已勾選項目、文字僅作註記。僅有文字時，可確認為不耗時、不耗資源的已保存註記。未確認的計畫不結算。
- **重大決策**：命名、主權承諾、結局等仍走各自明確確認流程；通用送出不構成批准。
- **操作性**：送出過程鎖定重複提交；失敗保留選取與文字，成功才清空。鍵盤可操作、焦點可見、手機觸控目標足夠，textarea Enter 保持換行。
- **驗收**：A27 更新；新增 A37–A42，並由 A43 驗收東漢末年視覺語言，見 `docs/ACCEPTANCE.md`。

## OV-2026-10-21-04：第四階段死亡救援邊界與版面重構

- **來源**：玩家對 PR #4 的最後規則核對及 UI 重構要求。
- **死亡節點**：原文未規定通用的 30 日緩衝。提示與行動中斷須發生於各節點觸發日；可調窗口由 `ENGINEERING.deathInterventionWindowDaysByEvent` 以事件 ID 個別設定。孫堅示例目前設 30 個模型日；未設定的節點於觸發日落實，不得繼承此窗口。窗口關閉或死亡落實後不得補開救援窗口。一般醫療使用示例物資；天生技不增加原文未規定的物資、冷卻或次數條件，仍須主角同地、直接且成功治癒才算有效介入。
- **軍事驗收解釋**：第四階段需實作指揮分工、唯一部隊位置、兵力守恆與跨線調動。多戰區內容規模可列為後續擴充，不能用來省略上述基本規則；兩線示例須可操作與測試。
- **出生／年齡**：184 年僅為預設／示例開局；新世界採玩家所選年份，出生年、世界日曆與年齡須相符。
- **UI 覆寫**：重構為敘事主欄、桌面精簡側欄、行動前可達的手機功能入口，天下消息簡短呈現。分頁／抽屜承載人物、家產、天生技與軍政；行動衝突和錯誤訊息留在文件流內，不以固定元素遮蓋正文。此為版面要求，不改變遊戲規則或存檔格式。

## OV-2026-10-21-05：第五階段自由文字與敘事服務邊界

- **來源**：玩家明確要求開始第五階段，維持規則 v3.15／天生技 v1.10 與第四階段既有遊戲狀態。
- **自由文字範圍**：補充文字先形成 `PlannedActionDetail` 候選，顯示意圖、順序、可辨識目標、方式與條件，再由玩家確認及規則引擎驗證。當前解析器只涵蓋四種已有生活行動的明確詞彙、已知在場人物拜訪、登錄人才招攬及「目標仍在場」條件。否定／例外、歧義、互斥行程、未支援命令先停下；玩家可明確只執行 checkbox 並把原文保存為註記，或只保存註記。未解析文字不會推進時間／資源。目標拜訪的信任增量 `ENGINEERING.playerVisitTrustGain=2` 是示例工程參數，非原文固定公式；招攬依既有 Phase 4 人才流程。
- **重大決策及能力**：天生技救治、死亡窗口、命名、主權條款、結局及其他軍政操作均維持專用流程，不由候選解析器自動批准或施放。
- **解析／敘事分工**：mock 使用前端本機確定性詞彙解析，故事由 mock 範本生成。`openai` 模式在 `/api/interpret` 將當次玩家原文、勾選意圖及候選目標交給 Responses API，回傳限四種生活行動的 JSON Schema 候選；在 `/api/narration` 將已結算結果與分層可知資訊交給敘事模型。兩者都無權修改遊戲狀態；解析候選必須由玩家確認，再由規則引擎結算。
- **行動範圍**：支援四種既有生活意圖、可驗證順序／方式、已知在場人物拜訪、已登錄人才招攬及「目標仍在場」條件。天生技、死亡救援、軍政操作、永久條約、命名、結局與任意長期／條件行動不由通用解析器執行。否定、歧義或未解析字串先要求澄清；真實解析失敗回退本機候選並明示來源。
- **資訊／金鑰**：只有真實行動解析會送出玩家該次原文；旁白不收到原文。旁白資料分開已結算事件、玩家視野／主角知識、實際在場 NPC 及各自已記錄知識。兩種請求皆不含完整存檔、帳簿或天生技後台。金鑰只由代理伺服器程序環境變數 `OPENAI_API_KEY` 讀取；不放前端、不提交、不寫日誌。`NARRATION_MAX_PROVIDER_REQUESTS` 限制每程序 1–100 次外呼（含自動重試），`NARRATION_MAX_OUTPUT_TOKENS` 限制每次輸出。
- **未驗證事項**：mock／假 adapter 已驗證，真實供應者連線、實際 token 費用、資料保留政策、長篇品質與多模型角色一致性尚待玩家在本機安全設定金鑰後測試；不得把 mock 或 fake adapter 宣稱為真實 AI 完整驗收。
- **存檔回歸**：第四階段 v6 IndexedDB 載入、續玩追加事件、重播、JSON 再匯入與再保存皆須維持同一世界線及原事件前綴；合法 JSON 序列化會忽略記憶體中未定義的 optional 欄位。
- **驗收**：A23–A24、A30、A44–A51，見 `docs/ACCEPTANCE.md` 與 `docs/PHASE5_REAL_AI_ACCEPTANCE.md`。

## OV-2026-10-28-06：依生命階段安排普通日常與先理解玩家輸入

- **來源**：玩家反映兩個月大主角被安排經商、詢問被誤當行動，並要求先辨識意圖與當下情境再確認結算。
- **普通日常**：十五歲以下不顯示經商、延攬人才或一般外出等成人生活選項；暫以觀察、聆聽、整理已有記憶、休息作可操作的在地日常原型。玩家可選每項 1、7、30、90 日。這些標籤和時長是工程原型，非原文另定的發育能力／成長公式。
- **引擎效果**：日常新增獨立版本化 `LifePlanResolved` 事件；逐日推進第四階段日曆並處理死亡等重大事件。只有完整完成項目記錄生活經驗；不憑空產生錢、成熟五維、旅程、親屬代辦或新 NPC 發言。一天內可複選成一回合計畫，回合後台只進行一次。舊事件 reducer 保留，原歷史存檔不重寫。
- **輸入順序**：區分 question、objection、dialogue、action、mixed、unclear；詢問／質疑不 dispatch、不因既有勾選而執行；混合／否定要求拆開。AI 只回覆及提候選，候選 ID 由當下選項白名單限制，玩家確認才派發。AI 無法明確辨識時本機回覆澄清。
- **能力例外**：普通生活面板的年齡分類不套用於天生技；天生技仍走原有獨立命令與逐能力 resolver。新日常計畫不宣稱改寫各技能目標條件。
- **界線**：NPC 對話事件／關係修正尚未完成；面板明示對話尚未實作，不假裝角色已回應。十五歲以上保留四種既有成人生活選項，但目標／路線和更完整人事限制尚待整合。

## OV-2026-10-30-01：新增受限的戰場剛體接觸示例

- **範圍**：新增 `ResolveBattleImpulse` 與 `AdvanceBattlePhysics`。只接受 `coordinateScale: "meters"` 且具位置、正半徑、質量、恢復係數的球形剛體；動量輸入後按物件間 3D 接觸法向、質量與恢復係數進行有限碰撞更新。短時推進沿當前速度常速移動，不含重力或外力。
- **工程參數**：接觸迭代數、接觸容差、穿透位置修正比例、剛體失效能量、示例物性、碰撞耗散平均歸屬接觸雙方的方式與速度上限均是可調工程設定，不代表史實器械資料。接觸模型只處理當前球形接觸，不做時間積分、形變、地形、風阻、人體或兵員模型。
- **效果界線**：可將本次碰撞耗散累加至剛體，並在達到清冊明列的能量門檻時標記物件失效；不由耗散能量推算傷亡、士氣或平民後果。舊 `ResolveBattleImpact` 與不含剛體屬性的存檔照舊運作。
- **驗收**：A271–A272；單元測試核對守恆／耗散、接觸與非接觸、穿透修正、失效門檻、子步預算、重播與舊存檔行為。§9.3C 仍未達出口。

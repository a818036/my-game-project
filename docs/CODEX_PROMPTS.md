# 可逐階段貼入 Codex 的指令

前提：本規格包的 `AGENTS.md`、`SOURCE_MANIFEST.json` 及 `docs/` 已放入 `my-game-project` 並提交。以下每段各是一個獨立任務；先驗收上一段再貼下一段。尚未把文件放入倉庫時，不要要求 Codex 從對話標題猜規則。

## 第一階段：建立可玩骨架

請在目前 my-game-project 倉庫實作「神洲三國」第一階段可玩原型。先檢查既有檔案與 AGENTS.md，讀取 docs/GAME_REQUIREMENTS.md、docs/TECHNICAL_SPEC.md、docs/ROADMAP.md、docs/ACCEPTANCE.md，以及 docs/source 中規則 v3.15 的開局、回合、帳務、自動後台章節。天生技基準是 v1.10，不能引用舊版代替。

採 React＋TypeScript＋Vite；若倉庫已有相容架構則沿用。完成繁中開局、姓名與出生確認、種子隨機、獨立世界線、十回合可玩的地方生活、四個互斥單一意圖選項、每回合天下大勢、五／十回合摘要、收合狀態與帳簿、IndexedDB 自動保存及 JSON 匯入匯出。規則引擎獨立於畫面，採命令、事件、版本與可重播的狀態轉移。小型測試內容要標示為示例，不能冒充完整歷史資料庫。

人事、人才、歷史節點、天下大勢四引擎需有可運作的小型案例；未完成的完整能力與自由文字解讀清楚標示，不假裝支援。先用範本敘事，不接付費 AI、不要求金鑰、不部署。完成 ROADMAP 第一階段出口及 A01–A07、A11、A27；實際執行必要的測試、型別檢查與正式建置，修復失敗。更新 README 的啟動方式與已完成／未完成範圍，最後回報可如何遊玩、檢查結果及變更檔案。

## 第二階段：人生、資訊與帳務

延續目前實作，先讀 AGENTS.md 與規格包，完成 ROADMAP 第二階段。建立家庭關係圖、血親／收養／婚姻稱謂、五維與普通技能限制、玩家命名決策、忠誠／恐懼／信任分離、恩怨紀錄、分帳流水、所有權與保管分離。加入場景在場者、人物首句年齡官職、單向通訊及消息到達、傷勢持續、15／20 回合摘要。不得破壞第一階段存檔；需要遷移時保留原存檔。用有實際操作結果的情境驗證 A08–A14、A25、A28，重跑受影響既有測試並完成建置。保持前台以故事為主、面板收合，最後報告可操作範例與未完成範圍。

## 第三階段：完整天生技

先完整閱讀 docs/source/神洲三國_軒轅天生技全錄_v1.10.md，對照規則 v3.15，完成 ROADMAP 第三階段。建立包含全部正式能力及派生式的登錄表，記錄原文位置與實作狀態；不要只實作摘要表列出的名稱。分群實作目標、排除、強度、直接／持續／次生效果與目擊資訊。

必須完整實作幻術分發模式×實相深度、威壓與忠誠分離、藏界容量無限但禁止人類活體及屍體、主角親自藏界＋閃物流、萬解物品不直接分解生命、防禦非護盾血量、治療與實歲／生理年齡區別。所有未明載的魔力、冷卻、數量限制與名將免疫不得新增。讓玩家能從介面選能力、目標與意圖，看到結算後果。通過 A15–A22，為原文其餘能力群加入必要行為測試；列出能力覆蓋表並完成型別檢查與建置。

## 第四階段：歷史、軍政與重大決策

依 ROADMAP 第四階段擴充世界。實作死亡硬節點及直接充分成功介入、已打破節點不重殺、史實事件核心因果與合理替代承載者、官職繼任、人才競爭、政策後效、路線與普通物流、土地控制五層、指揮鏈／兵員／補給／傷亡結算。主角親臨戰鬥依 v3.15 詳細呈現，目擊由局部傳播。重大主權承諾使用具體條款與授權範圍，不能把「去談判」當批准。統一後由玩家決定結局。

先用小型且來源標示清楚的歷史內容包，不捏造精確史實日期；未知精度存時間窗。完成 A23–A26、A29–A32，保留既有存檔遷移與前階段能力；執行受影響測試與建置，報告資料覆蓋範圍。

## 第五階段：AI 敘事與自訂行動

先讀 TECHNICAL_SPEC 的回合交易與 AI 分工。新增可替換的敘事供應者與伺服器代理，保留範本供應者作為無金鑰及失敗回退。先以 mock 完成整合測試；只建立環境變數範本，不寫入真實金鑰。選定供應者後查官方文件確認當前 SDK 與模型介面，不憑舊記憶硬寫版本。

將自訂文字轉成候選命令交規則引擎驗證；AI 不得直接改狀態。分開玩家、主角與各 NPC 所知，驗證日期、地點、在場者、數字及選項。重大語意不明時在遊戲內澄清，不能自動批准主權承諾。加入逾時、取消、有限重試與範本回退，敘事重試不得再次推進回合。完成 A33–A36 與人工敘事案例，說明自動檢查仍無法完全保證語意正確的邊界。不部署、不產生未經要求的付費用量。

## 第六階段：長局與發布準備

依 ROADMAP 第六階段整理有來源的歷史與地理內容、資料驗證、手機與鍵盤體驗、存檔遷移、長局回歸及效能量測。完成全份 ACCEPTANCE，人工檢查戰場、家族、政治與結局四類遊玩流程，修復發現的問題。整理可發布版本說明、實際內容覆蓋、已知限制與部署需求，但先不部署。不要把未驗證的全歷史覆蓋或所有 AI 敘事合規寫成已完成。

## 任一階段的修正任務

請先重現下列問題，再依兩份原檔與既有規格修正；不要修改原始規則來讓程式通過，也不要順便重寫無關模組。加入能重現問題的最小行為回歸測試，執行受影響檢查與建置，最後說明原因、修正與存檔相容性。問題描述：〔在此填入操作步驟、實際結果及預期結果〕。

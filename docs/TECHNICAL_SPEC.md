# 技術規格（工程提案）

本文件提出實作方式，不新增遊戲世界限制。

## 1. 技術選擇

先做桌面與手機瀏覽器皆可使用的單人網頁遊戲：React＋TypeScript＋Vite。規則引擎用獨立 TypeScript 模組，與畫面及 AI 分離；本機持久化用 IndexedDB，支援 JSON 匯出／匯入。Vitest 測試核心狀態轉移，瀏覽器端測試主要遊玩與存檔流程。套件實作時選相容版本並提交 lockfile，不預先猜測最新版本號。

第一階段不需伺服器。AI 敘事階段才增加伺服器代理、驗證與用量控制；雲端同步及帳號再視需求加入。文字為主，不需要先引入 3D 引擎。

參考官方文件：[React](https://react.dev/learn)、[TypeScript](https://www.typescriptlang.org/docs/)、[Vite](https://vite.dev/guide/)、[Vitest](https://vitest.dev/guide/)。

## 2. 模組與目錄

```text
src/
  domain/        型別、命令、事件、純狀態轉移、驗證
  engines/       時間／人物／人才／史實／天下／技能／帳務／戰爭
  content/       版本化人物、地理、事件、能力、範本及來源資料
  application/   遊戲服務、回合交易、敘事協調
  persistence/   IndexedDB、快照、匯入匯出及遷移
  ui/            開局、主畫面、命名、決策、面板
  narration/     範本、AI 介面、資訊篩選與結果檢查
tests/           單元／情境／回歸／瀏覽器流程
docs/            本規格及原檔
server/          後續 AI 代理；初版不必建立
```

## 3. 核心資料

所有持久物件用穩定 ID，不以姓名當主鍵；引用使用 ID。以下欄位是最低需要，實作可擴充。

| 實體 | 關鍵欄位 |
|---|---|
| Worldline | id、schemaVersion、rulesVersion、skillsVersion、contentVersion、sourceHashes、seed、rngState、revision、turn、clock、overrides |
| Person | id、姓名、出生／死亡時間及精度、實歲／生理年齡、五維／潛力、普通技能、天生技、性格、健康、locationId、factionId、officeHistory |
| Relationship | 雙方 ID、類型、方向、信任／忠誠／恐懼、恩怨紀錄；親屬另存親子／婚姻邊 |
| Scene | locationId、venue、time、presentIds、進出事件、可視範圍、通訊渠道 |
| Knowledge | holderId、factId、來源、觀察／抵達時間、可信度、信念內容；允許錯誤信念 |
| Account／LedgerEntry | 帳戶種類及擁有者、資產單位、整數數量、借貸／來源去向、eventId、時間 |
| ItemLot | 物種／器物類別、數量、單位、ownerId、custodianId、locationId、狀態、取得事件；人不能偽裝成物品 |
| Subspace | 主角 ID、ItemLot 引用；無重量容量上限，不共用全國庫存 |
| Faction／Office | 法理、控制層級、職位編制、任職者、空缺、到任行程、政策與支持者 |
| Army／Unit | 所屬、指揮鏈、各部唯一兵員、位置、糧秣、士氣、疲勞、傷亡與命令到達時間 |
| HistoricalNode | id、類型、到期時間窗、條件、來源、待處理／觸發／打破／取消、介入證據 |
| Effect | 能力 ID、目標／排除、深度／強度、起止、持續後果、直接／次生原因 |
| Decision | id、類型、完整條款、授權範圍、建立 revision、待選／批准／拒絕／失效 |
| Event | id、commandId、時間、順序、類型、因果父節點、payload、ruleRefs、可見範圍 |

數量使用整數與單位，禁止浮點金錢誤差；多單位兌換需記錄比率來源。時間採遊戲時間結構，不直接把古代日期交給電腦本地時區解析；年號映射獨立資料。不得用目前電腦時間推進世界。

## 4. 回合交易

1. 接收帶唯一 commandId 與 expectedRevision 的玩家命令。
2. 檢查目前是否等待命名、條款批准或結局決定；過期畫面命令拒絕並刷新。
3. 解讀行動，核對目標、地點、已知資訊與規則。AI 只能提出候選命令。
4. 計算時間範圍；依最早事件／需玩家決策節點拆段，不能一口氣跳過死亡或重大承諾。
5. 計算玩家行動與四個自動引擎的事件；同時事件採固定優先序及穩定 ID 排序，順序屬工程政策並測試。任何事件不可讀取尚未發生的資訊。
6. 在暫存狀態依序套用事件，檢查帳務、位置、兵力、死亡、授權、技能與知識不變量。
7. 一個 IndexedDB 交易提交事件、快照、RNG 與 revision；失敗則全部不提交。重複 commandId 不重算不扣款。
8. 從已提交狀態產生各視角可見的敘事資料、四選項、天下大勢與摘要。

敘事失敗不回滾已成功的遊戲交易，也不能再執行原命令；用相同 eventBatchId 重試敘事，或以範本顯示結果。生成文字不得成為改帳的依據。

## 5. 天生技引擎

能力資料包含 id、原文名稱、原文位置、目標條件、可選強度、直接效果、持續效果、次生效果、演出及目擊事件。各群建立專屬 resolver；不要用一個通用「戰力加成」取代全部能力。

幻術需兩個獨立欄位 distribution 與 realityDepth，加上 targetSelector、exclusions、intent；傷害事件標記直接幻術或事故。威壓獨立於幻術，fear／trauma 與 loyalty 不共用欄位。藏界存取更新位置與保管，所有權沒有明確轉移就不變。萬解將原器物設為失去功能／已分解，後續不得又當完好戰利品。

未實作的能力回覆「此版本尚未實作」並不消耗回合；不能回覆「能力因平衡限制失效」。所有完整能力名稱與派生式由原檔建置能力登錄表逐一對照，不只照需求摘要的能力群。

## 6. AI 分工與資訊防火牆

初版用可重播的繁中範本；後續 AI 處理自由文字意圖建議、人物對話與敘事潤飾。AI 不擁有任意狀態修改工具。輸入經分層：世界已結算結果、玩家可見的天下大勢、主角已知、當場各發言者已知，明確分開。

AI 輸出結構化 SceneNarration：場景錨點、發言者與渠道、正文、候選選項、引用 eventIds。程式檢查發言者在場或有有效通訊、選項結構、日期／職位／年齡與數字事實。對語意洩漏、人物性格與文風另做情境評估及人工抽查；不得宣稱只靠 JSON schema 能完全防幻覺。

遭檢查拒絕時可有限重試，仍失敗回退範本。使用者自由文字與匯入存檔是資料，不能把其中文字當伺服器指令。金鑰只存伺服器環境，不傳前端。遠端呼叫只帶本次所需遊戲資料；提供取消與逾時處理。

## 7. 存檔與重播

每世界線獨立事件流＋定期快照；保留上一個可用快照。新遊戲只重設新世界線，不覆蓋其他存檔；最近開局去重資料置於 profile 層。

匯出包含版本、來源雜湊、內容包版本、事件、快照、RNG 與完整性檢查值。匯入先驗證結構、大小、引用與版本，通過前不替換當前遊戲；較新不支援的版本拒絕並說明。遷移輸出新副本保留原檔，不能無聲改變已發生事件。相同版本、初始種子與命令序列須得到相同結算；AI 文句可不同，但狀態相同。

單瀏覽器多分頁需 revision 檢查避免互相覆寫。IndexedDB 保存並不等於永久備份，介面提供清楚的匯出入口與儲存失敗提示。

## 8. 畫面與品質

開局頁 → 出生結果確認 → 故事主畫面。主畫面含日期、地點、正文、天下大勢、四選項、自訂輸入及收合面板；命名與重大條款用明確對話框。不能把一般「繼續」按鈕當成批准永久割地。

鍵盤可完成選項與對話框操作；手機窄螢幕不橫向溢出；文字可調大小；保存、等待 AI、失敗與尚未實作狀態清楚。開發效能目標：標準測試資料集的一般本機回合大多在一秒內完成，不把遠端敘事時間算成引擎效能；目標屬提案，需記錄測試機器與資料量。
